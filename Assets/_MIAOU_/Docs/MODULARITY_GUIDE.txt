================================================================================
  ARCHITECTURE MODULAIRE — RESPONSABILITÉS & ANTI-REDONDANCE
  M2922 | VRChat / UdonSharp
================================================================================

  PRINCIPE CENTRAL
  ─────────────────
  Chaque fonctionnalité n'existe QU'À UN SEUL ENDROIT dans le codebase.
  Les autres scripts l'appellent via référence directe ou EventBus.
  Un module ne fait jamais ce qu'un autre module est censé faire.

  1. CARTE DES RESPONSABILITÉS EXCLUSIVES
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  ■ HealthController     → TOUT ce qui touche aux HP (donner/retirer/reset)
  ■ HitZone              → Calcul du multiplicateur de dégâts selon la zone touchée
  ■ ArmorSystem          → Absorption des dégâts AVANT HealthController
  ■ ResistanceTable      → Réduction des dégâts par type après ArmorSystem
  ■ BuffSystem           → Modification temporaire de stats (vitesse, résistances…)
  ■ TeamManager          → Appartenance à une équipe, friendly fire, score équipe
  ■ SpawnManager         → Choix du point de spawn, règles d'espacement
  ■ SpawnPoint           → Données du point (position, équipe, type)
  ■ InventorySystem      → Quelle arme/objet le joueur porte et dans quel slot
  ■ WeaponProp           → Logique de tir, munitions, rechargement
  ■ ProjectileSystem     → Physique et impact des projectiles physiques
  ■ ZoneTrigger          → Détection entrée/sortie d'un joueur dans une zone
  ■ GameMode             → Règles de victoire, états de partie, timer
  ■ ScoringSystem        → Calcul et attribution des points aux joueurs
  ■ KillstreakSystem     → Comptage de kills consécutifs et récompenses
  ■ RoundManager         → Succession des manches, scoreboard inter-manches
  ■ EventBus             → Diffusion de tous les événements inter-modules
  ■ M2922_Prop           → Cycle vie/mort/respawn visuel d'un objet de map
  ■ NpcController        → Comportement IA d'une entité non-joueur
  ■ VehicleSystem        → Sièges, physique, armement monté du véhicule

  2. PIPELINE DE DÉGÂTS — CHAÎNE UNIQUE, PAS DE RACCOURCIS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Toute source de dégâts (arme, zone, chute, explosion) DOIT passer par
  cette chaîne dans cet ordre. Jamais en court-circuit.

  SOURCE DE DÉGÂTS
      │
      ▼
  [1] HitZone.Evaluate(hit.collider, rawDamage)
      │  → Multiplie par le facteur de zone (headshot ×2, corps ×1, etc.)
      │  → Si pas de HitZone : multiplicateur = 1.0
      ▼
  [2] ArmorSystem.Absorb(damageAfterZone, damageType, zoneId)
      │  → Réduit selon l'armure de la zone touchée
      │  → Dégrade l'armure (perte de points)
      │  → Si pas d'ArmorSystem : passe tel quel
      ▼
  [3] TeamManager.CheckFriendlyFire(attackerId, victimId)
      │  → Bloque ou multiplie les dégâts si même équipe
      │  → Si pas de TeamManager : laisse passer (mode FFA)
      ▼
  [4] ResistanceTable.Apply(damageAfterArmor, damageType)
      │  → Réduit selon les résistances de la cible
      │  → Si pas de ResistanceTable : passe tel quel
      ▼
  [5] BuffSystem.ModifyIncomingDamage(damage)
      │  → Applique les buffs actifs (DamageReduction, Invincibility)
      │  → Si pas de BuffSystem : passe tel quel
      ▼
  [6] HealthController.TakeDamage(damageFinal, attackerId, damageType)
      │  → Modifie les HP — C'EST ICI ET NULLE PART AILLEURS
      │  → Si HP <= 0 : appelle Die(killerId)
      ▼
  [7] EventBus.Publish(OnPlayerDamaged / OnPlayerKilled)
      → Tous les autres systèmes réagissent ici (scoring, killstreak, UI…)

  RÈGLE : Aucun script ne modifie les HP directement.
          Tout passe par HealthController.TakeDamage() ou HealthController.Heal().

  3. DÉCOUPLAGE — QUI PARLE À QUI
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  RÉFÉRENCE DIRECTE (compatible UdonSharp)
  ─────────────────────────────────────────
  Autorisée uniquement quand les deux composants sont sur le même GameObject
  ou dans une relation parent/enfant immédiate.

    WeaponProp          → HealthController (cible, via GetComponentInParent)
    M2922_Prop          → HealthController (même GO)
    PlayerController    → HealthController (même GO)
    PlayerController    → TeamManager      (référence assignée en inspector)
    PlayerController    → SpawnManager     (référence assignée en inspector)
    HitZone             → HealthController (même GO ou parent)
    ArmorSystem         → (passé en paramètre depuis HitZone)
    NpcController       → HealthController (même GO)

  EVENTBUS (communication inter-module)
  ──────────────────────────────────────
  Utilisé quand les deux scripts ne sont PAS sur le même GameObject
  et n'ont pas de relation directe justifiée.

    HealthController    → EventBus.Publish(OnPlayerDamaged, OnPlayerKilled…)
    TeamManager         → EventBus.Publish(OnTeamScoreChanged)
    GameMode            ← EventBus.Subscribe(OnPlayerKilled, OnZoneCaptured…)
    ScoringSystem       ← EventBus.Subscribe(OnPlayerKilled, OnPlayerDamaged…)
    KillFeed            ← EventBus.Subscribe(OnPlayerKilled)
    KillstreakSystem    ← EventBus.Subscribe(OnPlayerKilled, OnPlayerDied)
    RoundManager        ← EventBus.Subscribe(OnGameFinished)

  INTERDIT
  ─────────
  × ScoringSystem  ne lit pas directement HealthController
  × GameMode       ne modifie pas directement les HP d'un joueur
  × WeaponProp     ne gère pas les équipes ni le score
  × TeamManager    ne connaît pas WeaponProp ni HealthController
  × SpawnManager   ne connaît pas GameMode (écoute OnGameStarted via EventBus)

  4. MODULARITÉ — COMPOSANTS OPTIONNELS PAR COUCHE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  Chaque couche est optionnelle. Si elle est absente, le système précédent
  passe les dégâts sans modification.

  COUCHE            PRÉSENT                     ABSENT
  ──────────────────────────────────────────────────────────────────────
  HitZone           Multiplicateur par zone     ×1.0 (dégâts bruts)
  ArmorSystem       Absorption + dégradation    Pas d'absorption
  ResistanceTable   Réduction par type          Pas de réduction
  BuffSystem        Modificateurs temporaires   Stats fixes
  TeamManager       Friendly fire, équipes      Mode FFA (tout le monde ennemi)
  SpawnManager      Spawn intelligent           SpawnPoint fixe ou absent
  GameMode          Règles, timer, victoire     Combat libre sans fin
  ScoringSystem     Points, classement          Pas de score
  InventorySystem   Gestion des slots           Arme unique non gérée

  RÈGLE D'IMPLÉMENTATION :
  Chaque script doit vérifier la nullabilité avant d'appeler un composant
  optionnel et fonctionner de façon dégradée sans lui.

  Exemple :
    float dmg = rawDamage;
    if (_hitZone != null)         dmg = _hitZone.Evaluate(hit.collider, dmg);
    if (_armorSystem != null)     dmg = _armorSystem.Absorb(dmg, damageType);
    if (_resistanceTable != null) dmg = _resistanceTable.Apply(dmg, damageType);
    _healthController.TakeDamage(dmg, attackerId, damageType);

  5. STRUCTURE DE PREFAB JOUEUR / NPC — SANS REDONDANCE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  PlayerObject (root)
  │   M2922_HealthController   ← HP, mort, respawn, regen
  │   M2922_PlayerController   ← Équipe, respawn point, stats, events
  │   M2922_ArmorSystem        ← (optionnel) absorption dégâts
  │   M2922_ResistanceTable    ← (optionnel) résistances par type
  │   M2922_BuffSystem         ← (optionnel) buffs/debuffs actifs
  │   M2922_InventorySystem    ← (optionnel) gestion des slots d'armes
  │   VRCPlayerObject          ← VRChat : lié au joueur local
  │
  ├── Body/ (collider corps ×1.0)
  │       M2922_HitZone        ← multiplicateur = 1.0
  │
  ├── Head/ (collider tête ×2.0)
  │       M2922_HitZone        ← multiplicateur = 2.0 (headshot)
  │
  ├── UpperBody/ (collider buste ×1.25)
  │       M2922_HitZone        ← multiplicateur = 1.25 (zone critique)
  │
  └── Limbs/ (collider membres ×0.75)
          M2922_HitZone        ← multiplicateur = 0.75

  NPC (root)
  │   M2922_HealthController   ← identique joueur
  │   M2922_NpcController      ← IA : patrol, chase, attack
  │   M2922_ResistanceTable    ← (optionnel) NPC lourd = résistant
  │   M2922_ArmorSystem        ← (optionnel) boss = armure forte
  │
  └── HitZones/ (même structure que joueur)

  RÈGLE : HealthController est IDENTIQUE sur joueur, NPC, véhicule, structure.
          Seuls les composants autour changent.

  │   VRCPickup                ← VRChat : rendre ramassable

  CE QUE WEAPONPROP NE FAIT PAS (délégué) :
    × Calcul des dégâts finaux sur la cible → HitZone + ArmorSystem le font
    × Vérification friendly fire           → TeamManager le fait
    × Attribution du score/kill            → ScoringSystem écoute sur EventBus
    × Gestion du slot d'inventaire         → InventorySystem le fait

  7. ADAPTABILITÉ — CONFIGURATIONS TYPE SANS MODIFIER LE CODE
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  CONFIG A — Combat libre (Sandbox)
    Composants actifs : HealthController, WeaponProp, SpawnPoint simple
    Composants absents : TeamManager, ScoringSystem, GameMode, HitZone
    Résultat : Les joueurs se tirent dessus, meurent, respawnent. Rien d'autre.

  CONFIG B — FFA avec score
    Composants actifs : A + ScoringSystem + KillFeed
    Absents : TeamManager, GameMode
    Résultat : Score individuel affiché, pas de règles de fin.

  CONFIG C — Team Deathmatch complet
    Composants actifs : B + TeamManager + GameMode(TDM) + SpawnManager
    Absents : HitZone (dégâts uniformes), ArmorSystem
    Résultat : Equipes, score limite, timer, friendly fire.

  CONFIG D — Simulation réaliste
    Composants actifs : Tous
    HitZone (headshot ×2.5, membres ×0.6), ArmorSystem (armure lourde),
    ResistanceTable, InvenorySystem (2 slots armes), GameMode(S&D)
    Résultat : Gameplay tactique complet.

  CONFIG E — Horde PvE (joueurs vs NPC)
    Composants actifs : HealthController, NpcController, SpawnManager (NPC),
                        WaveSystem (GameMode custom), ScoringSystem
    Absents : TeamManager (NPC toujours ennemis), InventorySystem
    Résultat : Vagues de NPC, score par kill, pas de teams entre joueurs.

  9. RÉSUMÉ — RÈGLES D'OR
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. UNE FONCTIONNALITÉ = UN SCRIPT. Jamais dupliquée.

  2. PIPELINE DE DÉGÂTS INVIOLABLE.
     HitZone → Armor → FriendlyFire → Resistance → Buff → HealthController.

  3. TOUT COMPOSANT OPTIONNEL EST NULL-SAFE.
     Le code vérifie toujours (if _system != null) avant d'appeler.

  4. COMMUNICATION INTER-MODULE = EVENTBUS.
     Si deux scripts ne sont pas sur le même GO, ils parlent via EventBus.

  5. AUCUN SCRIPT NE CONNAÎT SON CONSOMMATEUR.
     HealthController ne connaît pas ScoringSystem.
     Il publie sur EventBus. ScoringSystem écoute. C'est tout.

  6. HÉRITAGE POUR LA STRUCTURE, EVENTBUS POUR LA COMMUNICATION.
     M2922_Prop est une base → WeaponProp hérite.
     WeaponProp ne parle pas directement à ScoringSystem → via EventBus.

  7. LES GAME MODES NE MODIFIENT PAS LES DONNÉES DIRECTEMENT.
     Un GameMode publie des commandes sur EventBus, les systèmes réagissent.
